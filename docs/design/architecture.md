# 架构与模块边界

CimStats 是 Python 3.12、PySide6 与 PySide6-Fluent-Widgets 桌面应用。保留现有模块边界，不为文档整理改写目录、业务或构建入口。

## 数据流

```text
.save -> 容器解压 -> 隔离运行时解析 -> 对象与历史数据
      -> 公司／网络／城市／最新信息模型 -> 查询快照
      -> 桌面展示、图表、XLSX／PNG 导出
```

- [save_container.py](../../src/save_container.py)定位负载；[extract_runtime_data.py](../../src/extract_runtime_data.py)加载解析用运行时。存档及原程序集不原地修改。
- [history_contract.py](../../src/history_contract.py)定义历史窗口和观测契约；[statistics_model.py](../../src/statistics_model.py)、[network_model.py](../../src/network_model.py)、[city_model.py](../../src/city_model.py)、[latest_info_model.py](../../src/latest_info_model.py)承担业务聚合。
- [statistics_page.py](../../frontend/statistics_page.py)协调筛选、模式与快照；[company_dashboard.py](../../frontend/company_dashboard.py)、[network_dashboard.py](../../frontend/network_dashboard.py)、[city_dashboard.py](../../frontend/city_dashboard.py)负责呈现，不重算另一套分母。
- [chart_canvas.py](../../frontend/chart_canvas.py)是共享绘图入口；[stats_charts.py](../../frontend/stats_charts.py)、[network_charts.py](../../frontend/network_charts.py)、[chart_details.py](../../frontend/chart_details.py)提供图卡、身份图例与放大详情。不得把已替换的 QtCharts 或外部 Pro 控件写成依赖。
- 导出读取展示所用查询快照；分类显隐、悬停和放大不改变业务值。过期异步任务不得覆盖最新快照。
- 静态 PNG 渲染完整快照时暂时禁用透明效果，避免永久／过渡透明宿主使图形缺失或淡化；完成或失败后恢复原启用状态，不修改界面动效策略。
- 统计页面将存档当前规范化线路的副本随网络模型任务传递；模型仅对所选公司的理论最大需求求和，并在快照中记录当前值上下文。需求摘要与历史平均车辆图分开取值，当前需求不构造历史比较，导出直接读取该快照。

## 地图模型与查询

地图快照接管先完成隐藏页面的实际布局，再按画布可用尺寸恢复或拟合视角；独立地图页面与主窗口堆叠页共用此入口，不能用未布局的初始尺寸固定全城缩放。快照接管、首帧准备和异步绘制失败均结束加载状态，在地图底栏保留失败原因并释放当前请求，重新进入地图可重试。后台探针生成与元数据恢复复用同一次源程序集元数据读取，恢复后的探针内容与独立读取一致；不增加持久化存档缓存，也不省略地图对象。

[map_vector.py](../../frontend/map_vector.py)从独立查询快照准备世界坐标矢量批次，保留道路、建筑和真实路口几何。[map_canvas.py](../../frontend/map_canvas.py)维护数据代次、导航、命中和导出状态，[map_vector_canvas.py](../../frontend/map_vector_canvas.py)负责原生矢量呈现。世界几何与屏幕符号分别变换，缩放按当前尺度更新线宽与细节。地图页面及搜索、图例、规划菜单保持既有控件结构。

[map_gpu_geometry.py](../../frontend/map_gpu_geometry.py)在后台将世界几何编译为不可变顶点、索引、材质和绘制范围；[map_gpu_renderer.py](../../frontend/map_gpu_renderer.py)按查询代次上传并保留显卡缓冲。平移、缩放只更新视角和当前可见绘制范围，不重建路径、不上传全图。道路线宽、车道边界、线路线宽及虚线节奏由着色器使用共享公式计算。闭合车道轮廓通过有向三角扇、非零绕数模板和覆盖填充处理，保留自交语义与源、目标道路的投影渐变。原生抗锯齿边缘保留不透明背景，画布和窗口合成必须像素一致。

底图与线路分别持有显卡缓冲。选线、方向和线路样式变化复用道路、路口与建筑；底图筛选或配色变化按其数据身份重新准备。道路与路口的内层、外沿共享同一份几何，通过材质和绘制阶段计算宽度。独立闭轮廓分别完成非零填充，不能叠加绕数后相互抵消。[原生提交组件](../../frontend/native/map_gpu_submit.c)按既有顺序提交状态和索引范围，所用函数指针属于当前显卡上下文；调用前核验缓冲范围，缺少组件时由 Python 保留同样的绘制规则。构建与源码冻结同时纳入组件来源。

[map_gpu_strip.py](../../frontend/map_gpu_strip.py)在后台检查车道轮廓的内层与外沿。只有在完整适用缩放区间内能够确认三角形方向、相邻边和非相邻边关系的轮廓，才使用共享三角条直接绘制；检查包含着色器单精度运算的误差范围。检查失败、数值不确定、轮廓过大或组件不可用时，继续逐个轮廓执行非零填充。该检查保留原始顶点，不调整线路位置或路口形状。

[map_gpu_visibility.py](../../frontend/map_gpu_visibility.py)将过大的普通绘制范围切分为连续索引段，保留原顶点、图元顺序和物理宽度边界。渲染器为命令和路口成员建立空间索引，复用视口邻域候选及工作数组，每帧重新计算精确可见性和叠放顺序；密集视口使用连续数组扫描。视口外命令的成员仍可影响路口块顺序。原生提交仅合并状态相同、索引连续且图元完整的相邻普通三角形，非零填充和状态切换保持原边界。

缓冲上传直接读取常驻数组。隐藏页面在矢量和显卡几何准备完成后可报告数据就绪，不重复绘制完整软件预览；页面显示及导出仍等待当前视角的实际完整帧。显卡失败时按需准备软件帧，过期软件任务在绘制批次之间协作取消。[map_gpu_stroke.py](../../frontend/map_gpu_stroke.py)使用构建时生成的原生轮廓计算组件，位置、连接和虚线弧长与 Python 路径一致；不可用时保留原实现。

[map_gpu_annotations.py](../../frontend/map_gpu_annotations.py)按查询保留站点关联与线路标签候选，按字体、设备 DPI 和像素比保留文字轮廓；每帧批量变换候选坐标并复用绘制状态，站点仍由既有 QPainter 符号绘制。标签避让及低倍去重保持原顺序。原始停站坐标和运营区段符号位置保持独立。显卡上下文销毁时释放原生资源及其候选索引；重新建立上下文后重新上传。没有可用显卡时以及图片和 PDF 导出继续使用原有世界矢量绘制入口。

[map_scene_cache.py](../../frontend/map_scene_cache.py)保留当前存档近期使用的不可变 CPU 场景，最多六组、保守记账不超过 1.5 GiB，共享底图与源几何按持有者计一次。缓存键包含源对象、完整显示选项及绘制配色；换存档、清空或关闭画布时释放，超预算场景仍可正常显示。缓存不持有显卡上下文、绘图设备或字形状态，不写入磁盘。视角设置实时更新内存，停止导航约 300ms 后合并持久化；切换预设、换存档及关闭前保存最终视角。显卡资源释放或上下文重新初始化时失效呈现状态，导出在新帧完成后恢复。

退出事件循环后，启动入口取消画布任务并等待后台绘制结束，在应用对象仍存活时同步销毁主窗口、隐藏绘图表面和绘制上下文。启动失败时也等待导入线程退出。仅关闭或隐藏窗口会延后这些资源的释放，无法保证 Qt 内部绘制资源在应用对象销毁前完成清理。

软件绘制入口按保存顶点批量计算车道边界，Qt 多边形的批量写入须先验证运行时内存布局，不满足时使用逐点构造。展示选项与世界几何分别失效；隐藏帧完成后可交接已准备的绘制值，工作线程与界面线程不并发修改缓存。原生视口仅在数据代次、视角、尺寸、设备像素比、字体、高亮、帧缓冲和上下文均相同时复用完成画面；新视角使用常驻矢量几何绘制。

[map_scale.py](../../frontend/map_scale.py)统一线路与站点的连续缩放曲线，具体函数及像素口径见[地图显示](../requirements/map-display.md)。已知道路米宽与世界坐标等比例缩放，线路分组独立于视角缓存，沿保存路径允许自然重叠。[window_chrome.py](../../frontend/window_chrome.py)在原生主窗口创建时准备隐藏绘图表面，随后安装既有边框和阴影，避免异步地图加入时重建已显示的窗口；辅助窗口保持原有样式。

[map_visibility.py](../../src/map_visibility.py)提供运营方向与站点符号的关联规则。地图索引后台准备时缓存各运营区段的站点制图端点；绘制、站名、高亮和搜索定位复用同一映射，筛选后按可见线路的绘制顺序保留一个站点符号。原始停车坐标不变，制图端点不参与服务覆盖、里程或方向分析。

矢量空间块查询根据视口范围选择较小的遍历集合：常规视口查询对应网格，极远视口筛选已存在的块。视口覆盖整城或远离地图时，查询工作量受已有块数量约束，避免按空区域面积增长；路线、车道及小几何的既有显示阈值继续生效。

道路与车道连接的空间边界包含实际米宽，线路裁剪范围按实际像素线宽扩展。中心线在视口之外、实际笔画仍覆盖视口时继续绘制，避免平移后突然出现；细节层级仍以原始曲线跨度判定。

[map_model.py](../../src/map_model.py)保存不可变几何与原生方向段数据，[map_query.py](../../frontend/map_query.py)按稳定线路身份接入真实统计，统一计算客流来源、平均间隔口径及盈亏分类；面板、颜色解析器与导出复用查询结果，不各算一套。方向里程采用原生段计数；方向时长优先使用停站到达偏移，失效缓存按原生距离、车型及停站规则逐段复算，保存在同一不可变快照中。全线和方向计算共享 [line_duration.py](../../src/line_duration.py) 的整数公式及同一帧时长入口，绘图几何不作为统计替代。

[map_panels.py](../../frontend/map_panels.py)维护六个筛选块的独立草稿和已应用状态，确认只提交本块，公开状态及预设持久化只含已应用值；程序恢复清除待编辑状态，显示设置即时应用并保留其他草稿。[map_page.py](../../frontend/map_page.py)协调查询、预设、完整目录与结果数量，组件更新不重复解析存档。具体默认值、交互与布局见[地图显示](../requirements/map-display.md)及[控件契约](controls.md)。

## 共享界面与布局

- [app_shell.py](../../frontend/app_shell.py)统一导航、页面标题、文件区和子选项卡；[ui_kit.py](../../frontend/ui_kit.py)、[stats_controls.py](../../frontend/stats_controls.py)统一控件。
- [stats_icons.py](../../frontend/stats_icons.py)统一带颜色的 Fluent SVG 图标，保持原始几何与颜色，由 Qt 原生 SVG 图标引擎按设备像素比绘制。按内容缓存的 SVG 临时文件保留到应用退出，避免惰性加载时丢失资源，也避免 Python 图标引擎在循环引用回收时发生所有权释放冲突。
- [stats_tokens.py](../../frontend/stats_tokens.py)和[stats_typography.py](../../frontend/stats_typography.py)是颜色、尺寸及字体入口，不复制局部主题。
- [startup_surface.py](../../frontend/startup_surface.py)提供主窗口初始 Logo 遮罩与欢迎层共用的窗口预算、背景及标志坐标，不导入 Fluent 或业务模块。[startup_welcome.py](../../frontend/startup_welcome.py)在中央窗口覆盖导航和页面顶栏，负责首次打开入口与标志上移动效；`app_shell.py` 的正常页面顶栏保持独立。
- [startup_bootstrap.py](../../frontend/startup_bootstrap.py)先创建轻量主窗口，在[首帧门控](../../frontend/startup_readiness.py)确认 Logo 遮罩完成绘制后才调用 `initialize_content_async()`。后台准备依赖与类定义，主题和全部控件仍在主线程按事件回合构建；Logo 遮罩保持覆盖至所有页面就绪，再在欢迎层首帧绘制后启动过渡。构建期间仅窗口系统按钮可操作，业务输入和拖放在就绪后启用。同一原生窗口从 Logo 持续到欢迎与业务页面；正常启动不运行独立 helper。不透明子表面可能使 Qt 省略外层窗口绘制事件，门控必须覆盖这一分支。[启动传输](../../frontend/startup_transport.py)仅保留兼容诊断入口的鉴权与回收。解析与图表准备覆盖欢迎层，成功准备后显示页面，失败或取消返回欢迎层；取消后已经排队的完成结果不得重新载入。
- [window_chrome.py](../../frontend/window_chrome.py)复用现有无边框 Windows 窗口层提供共享自绘标题栏、系统移动／缩放与应用文件选择入口。仅导入存档使用 Windows 原生打开文件对话框，其系统外观是应用自有窗口标题栏规则的例外；其他应用自有窗口继续共享自绘标题栏。主窗口标题只有应用名称并显示应用图标；独立二级窗口隔离默认图标继承。已有 Fluent 遮罩弹层与菜单、工具提示保持原有形态。
- 统计页固定标题／文件操作、子选项卡、筛选；数据区共用一条纵向滚动，不为各公司另设滚动条，不产生整页横向滚动。
- 默认与同期各公司分组；多公司比较公共图。公司数量不改变模式。公司单栏四个指标图位固定，宽屏双公司对应行对齐，窄屏重排而不丢数据。
- 分析模式能力依据存档有效公司身份判断，单公司替换时清理失效的多公司模式；勾选数量只决定查询范围。共享画布在每种绘制路径按紧凑／放大身份控制数字数据标签；仅首页“客流结构”“班次结构”分布图允许小图常驻数量，其他小图不能由单系列或足够空间绕过禁标签规则。
- 内容宽度与显示预算由布局控制，不能用固定最大高度裁掉数据。摘要折叠必须释放真实绘图区高度；普通 resize 不重建整个图控件或反复查询。
- 统计动效的布局请求合并处理，只拟合当前堆叠页的可见区，隐藏页在显示前按最终尺寸布局。卡片阴影按位置、裁切及透明度变化刷新旧、新覆盖范围，实际内容和输入规则保持原样。

## 文件与输出

源码入口 `CIM2_SaveStats.py` 和兼容的 `CIM2_*` 名称继续有效，产品显示名为 CimStats。`data/`、`game_runtime/Managed/`保留构建与解析依赖；`exports/`仅跟踪复用的目录数据。真实存档、解析中间文件、截图和构建产物放在忽略的 `jobs/`、`build/`、`dist/`，不成为文档树的一部分。

构建和验证见[开发说明](../DEVELOPMENT.md)、[发布说明](../RELEASE.md)及[验收清单](../testing/acceptance.md)。
