# 父会话亲自核对的旧分析图交互基准

依据：尚未合入新首页的主工程 `D:/test/CIM2_SaveStats/frontend/desktop_app.py`，`ChartPanel` 496–609、`refresh_company` 1458–1527、切换回调1529–1544。此文记录实际源码行为；视觉审计和修订以用户最新要求为准。

客流与班次是两套独立但对称的状态机。全页公司/制式先筛选线路；每图另外持有 `view`（stacked/ranking）、图内mode及 `pie_expanded`，不能把这些状态简化成一个下拉选择。

| 原状态或入口 | 旧真实行为 | 恢复必须检查的内容 |
|---|---|---|
| 默认综合结构 | 同时展示按制式的原始总量堆积条、比例饼图、完整制式数值列表；标题展示合计 | 总量与占比两种编码均保留，不能只剩排行或环形图 |
| 堆积条点击某段 | `BarCanvas.clicked_mode`→对应segment handler→该制式线路Top10 | 使用真实mode标识，降序且最多10条；不修改全页筛选 |
| 制式列表的箭头 | 同一个clicked_mode路径 | 列表与图段入口等价，完整类别不能丢 |
| 制式饼图点击扇区 | series.clicked→mode钻取；generic pie click延迟一轮并被segment优先拦截 | 单击不能同时钻取和展开；颜色/身份不能取显示标签猜测 |
| “综合Top10”按钮 | stacked→ranking，图内mode清空，当前全页范围内综合降序Top10 | 保留图内与全页两层范围；图内无mode时名称带制式 |
| 模式排行 | 隐藏饼图和制式列表，以横向条形展示线路及实际数值 | 客流单位人次，班次单位班；完整10条有空间 |
| “返回堆积图” | ranking→stacked，图内mode清空，重建综合结构 | 返回的是原制式综合结构，不是另一份综合Top10 |
| 饼图通用点击 | `show_pie_details`在原卡内部展开Top10线路＋其他占比图 | 这是同卡展开，不是原有模态弹窗；不用伪造新流程替代 |
| 线路占比展开 | 取当前全页范围Top10；其他=完整总量−Top10合计，正值才加；图例列名称、原值和对全量总数的占比 | 不能只按Top10重归一化到100%；不能删除其他 |
| “综合图”返回 | pie_expanded优先→restore_aggregate_pie，不进入ranking切换分支 | 恢复堆积条、制式饼图和列表及原单位/范围 |
| 客流/班次独立操作 | 两图各有view/mode/expanded，不相互覆盖 | 操作一图不重置另一图；全页数据更新按同一快照刷新 |
| 清空或导入新会话 | 清值、pie_details、aggregate_pie、expanded及旧分类行 | 新会话不遗留旧展开数据/入口 |

客流综合结构采用万人次显示原总量，线路排行和线路占比展开采用人次；班次始终为班。综合结构不止装饰图，而是总量概览、占比概览和制式钻取的共同入口。

旧实现还有标识混用风险：aggregate的slice.label会被设置为“制式 xx.x%”，而 `_on_pie_segment`直接发slice.label，随后按精确mode筛选可能失配。修订应保留正确的制式钻取意图、用稳定标识分离显示文字，不能为了“保留”复制此实现缺陷。旧 `ChartPanel` 本身没有类别图全屏入口；不要把统计页时间图/新增今日趋势的全屏能力误写成旧类别图必备能力。

现版源码中，客流 `PassengerRanking` 主要是排行＋制式下拉，返回设置下拉综合仍是排行；班次 `DepartureStructure` 为环形图/列表＋排行。上述二者不能被视为旧 `ChartPanel` 三状态全功能等价。
