### 状态与范围合同

## 结论：当前版不可接受，必须修订后重新验收

用户“比以前更杂乱”的反馈有具体依据。当前版虽然增加了必要信息，却把原来宽阔、完整、可钻取的两张统计图，变成一张很淡的排名列表和一张缩小的班次环图。提醒栏从顶部一直占到页底，压缩分析区；13 个指标、16 个极值数字和提醒动作几乎等权。问题不是缺少装饰，而是结构、空间分配和功能保留不足。

### 旧源码本身的缺陷必须单独处理

## 3. 数据口径边界：本次视觉修订不能重算业务

源公式在旧 desktop:1464–1495，新 `src/latest_info_model.py:250–278`。完整有效记录下，线路数、车队、行车分钟、班次/车队、线路周收入/支出/利润、有效日组内相邻间隔平均、正核定速度均值、总客流/总班次、总客流/Σ(班次×地图里程)的主口径一致。

不能笼统声称完全数值等价：新 `_sum/_ratio/_measurement`（94–106）不把缺测或零分母当有效零；旧代码多用默认零。新 model:229 会排除无法解析到已知公司 ID 的线路，而旧全公司选择可能包含它们；新 interval:146 校验合法时分，旧未做同样校验。应保留已审计的安全缺测机制，对这些边界做显式回归，不能为恢复图形而回退成“缺测=0”。

两类总量必须分清：结构图/排行取 `LineSummary.passengers/departures`（线路快照及全日计划班次）；小时趋势取历史查询（model:310–316）。不能要求趋势合计强行等于线路快照总量。占比“其他”只能由同范围同指标的完整有效线路总量减去十条；总量缺测时不计算伪百分比，应显示“总量不完整”，列出已知量。

全市公共交通分担率（model:304–306、325–326）、所选公司全部制式换乘系数（169–214、297–320、327–329）维持其作用域；不要把换乘系数简单平均、随制式下拉错误收窄，或给高低加业务评价。卡面分别常驻“全市”和“所选公司·全部制式”短标记，详细公式置说明入口。

Hero 当前显示 quicksave/“秋山市n6 (2)”不仅是版式问题：`src/extract_runtime_data.py:883–888` 在没有真实地图/场景名时退回 `SAVE.stem`，最终统一写入“地图名称”（901）。多人真实缓存元数据也确实如此。新 page:400/model:346 无法区分来源，遂把文件名当城市展示。最小安全修复是保留来源标识；真城市名才用城市标题，文件名回退明确称“存档”，缺城市名明确显示未提供。不能根据文件名擅自推断或裁掉 n6 来制造一个城市名。

班次缺测时还需核对分母：新环图按正有效类别自身合计归一化（charts:273–280），而列表百分比用 `total_departures`（333–334）。总量为 None、部分分类有效时，环仍可能画出完整 100% 圆，列表却为“—”。恢复两图时须明确标注“已知类别占比”或不显示完整分布，不能让这两者呈现为同一完整全网占比。

## 4. 为什么现在更乱：逐区域修订

### 顶部和 Hero

操作栏基本可保留；打开存档保持唯一主按钮。导出 XLSX 当前灰显由文件可用性控制，不从截图推断按钮失效。将文案统一到“导出线路 XLSX / 导出公司 XLSX”，不增加常驻按钮。

Hero 现为四个等宽字段，城市列只分到约 220px，长文件名成为巨大的省略号；日期比“模拟日期与时间”标签还弱，城市、时钟、人口缺乏整体阅读顺序。保留无插画的白色/Mica感容器，用 30/24/22/24 比例分配四字段；城市 29px，时间/人口 21–24px，日期正文 13–14px，来源存档 12–13px。弱化“城市”“模拟日期与时间”重复提示；城市不可用时就说不可用。文件名允许明确的中间省略并保留完整 tooltip，绝不能把数字/单位截断称为可用。

### 指标和范围

现在 4+5+4 行虽“齐全”，但最后一行留一格空位，格线边缘又与上面四列和下方四张极值错开；重复蓝色饼图图标没有区分指标，造成视觉噪声。所有标签基本深蓝，辅助说明没有退到次级。

范围行左侧写“核心运营指标”，右侧“数据范围：[公司] [制式] [说明]”。删除常驻的“线路今日客流与全日计划班次来自存档快照……”长句，把完整解释放到说明弹层/tooltip。分担率/换乘系数例外范围留在对应卡面。不要把公司稳定 ID 当普通页标题；同名公司确需区分时显示短识别号并保留完整身份。

核心四格保留：线路总数、车辆总数、每周收入、净利润；主数值 23–24px。辅助九格保留 20–21px 数值、12–13px 标签。辅助可保持 5+4，但第二行用四等宽格铺满辅助宽度，或使用明确的“效率/全市与换乘”子分组；不能留一个看似缺失的空卡槽。最多核心四项使用不同且有意义的 16px 图标，辅助重复饼图图标去掉。边框、圆角沿用共享 tokens，不增加第二套重描边。

### 线路亮点

当前四张极值卡内四个数字都是 21px 半粗，16 个数字争夺注意力，线路名只有 14px，且制式隐藏到 tooltip，和原版“有轨电车107路”相比更难识别。

加共用“线路亮点”标题；每卡先显示制式＋线路名（14–16px），右侧小型“最大客流/最小客流/最多班次/最少班次”标签。下面四行统一“字段—数值—单位”对齐，正文 13px，只有该卡极值对应数字 18–20px，其余数字 13–14px。四字段全部常驻；这是建立层级，不是缩小全页字体。公司同名线路以 tooltip/详情补齐，并始终按 key 跳转。

### 提醒

当前 5 条提醒各有两个 26px 按钮，连同开关、阈值、全部、全部已读形成大量动作块；长数值无千分位、没有良好字段对齐，且整块高度一直延伸至图底。它看起来像设置表单，权重超过分析图。

改成上半部 260px 宽摘要栏：标题＋未读数＋“全部”；每行 76–88px，标题、对象/范围、前后值最多三行，点击行打开详情，键盘 Enter 可操作。已读动作放详情或行尾小按钮；阈值、开关、全部已读放明确“更多”菜单。能力全部保留，常驻动作减少。保持至少 3 条，有空间显示 4–5 条；无有效提醒时显示真实空态，不造够三条。金额用千分位，前后方向和单位保持准确。

当前只是 `alerts[:5]`（frontend/latest_info_alerts.py:277），源模型按指标枚举追加（src/dashboard_model.py:37–57），并不能证明是“最重要五条”。先复用现有 Alert 字段定义可解释的排序；没有真实严重级别时使用中性蓝点，不凭空配红黄“危险”等等级。不改前一完整模拟日对前一日的查询窗口（src/latest_info_alerts.py:8–18），不用宣传图里的 14:20 等假时间。提醒仍有公司/全市混合范围，短注明“所选公司及全市 · 前一完整日”。

### 下方分析

旧版合理部分是：两图拥有清晰标题和总量，堆积条说明绝对量，饼图说明比例，列表说明准确分类量，明确按钮进入 Top10 并能回来。当前客流变成 21px 行高、10% 不透明度背景条（charts:125、153），条形被文字压在背景里，更像选中表格；班次直径 74px，周围却大面积空白；趋势约 255px 宽，只剩两个横轴刻度。此处是空间分配问题，不是应当继续缩小字的问题。

恢复两个结构卡，图内仅使用有数据意义的颜色。排名恢复“线路标签｜独立条形轨道｜精确数值”三列，避免数值浮在淡色行背景上。综合态可用统一蓝条＋制式小圆点，制式态用对应色；数字右对齐。趋势继承共享折线实现，`QLineSeries` 和 None 断线（stats_charts.py:1072–1087）应保留，不换平滑曲线；把线/面积切换收为卡头菜单，默认折线，将省出的行留给绘图区。

当前制式颜色由首页独立位置映射（charts:98–101），统计图另有 `_category_color`（stats_charts.py:518–524）。应按规范制式 key 复用一份映射，不能仅因采用同一 palette 就宣称同制式颜色一致。未知制式要可区分，不能全部落到一个相同色槽。
