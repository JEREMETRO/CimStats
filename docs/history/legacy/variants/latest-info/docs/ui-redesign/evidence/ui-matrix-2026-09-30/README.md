# 当前统计界面一致性核验（修复前）

2026-09-30 使用当前主项目代码和两份已解析的真实存档缓存，检查了 130 个界面状态：单人／双人存档 × 五种 Qt 逻辑窗口尺寸（920×680、1440×960、1600×1000、1920×1080、2560×1440）× 公司默认／多公司／同期、网络总体／多公司／同期、城市页面，以及筛选栏展开／折叠。单人网络多公司模式因控件禁用而未计入。

## 发现

- 公司多公司模式的 20 个状态均有独立的“满意度维度”下拉行；单人模式一张卡片、双人模式两张卡片，共 30 个卡片实例仍保留静态“速度满意度”标题。下拉菜单没有替换标题。根因在 `frontend/company_dashboard.py`：只在 `charts=True` 时创建卡片内下拉；多公司模式传入 `charts=False`。`frontend/statistics_page.py` 只在该模式显示独立工具栏。失败截图留在本目录。
- 默认与同期模式的满意度下拉已经位于 KPI 标题行。
- 130 个状态中未检出横向滚动或图表矩形重叠；1440 像素及以上窗口的公司默认／网络总体模式未检出纵向滚动。网络复杂模式及窄窗口有纵向滚动，需按原先允许滚动的要求判断。

`matrix.json` 保存每个状态的窗口、滚动和卡片数据；`../../qa_ui_matrix.py` 是核验脚本。最初运行时误停留在概览页产生的 50 张截图已原样保存在 `superseded-overview-captures/`，不作为统计页面证据。

此次是 Qt offscreen 下的逻辑窗口尺寸检查，使用解析缓存；并非 Windows 原生屏幕缩放、最大化窗口、Mica 效果或重新解析存档的验证。

## 修复后的独立复验

界面子会话将满意度下拉创建移至所有公司模式共用路径，并移除卡片下方的独立工具栏后，针对受影响的多公司模式重新检查了单人／双人 × 五种尺寸 × 筛选栏展开／折叠共 20 个状态。`after-fix/matrix.json` 的问题列表全部为空；`after-fix/` 保留 20 张对应截图。人工查看了 920×680 展开、1440×960 展开和 2560×1440 折叠截图，均为卡片标题行内下拉，独立行消失。针对标题替换、模式一致性、两个公司同步及偏好保存的 15 项检查通过。

这一结论针对界面子会话当前工作区代码；提交与主线程整合状态以其后续报告为准。

界面子会话随后收窄“六进公交／八连交通集团”标题行。对此最新版又定向重复上述 20 状态检查，结果仍为零问题，见 `after-title-tightening/matrix.json` 和同目录截图。人工查看了 920×680 与 1440×960 双公司展开截图：公司名称、折叠按钮和满意度标题下拉均未互相遮挡；窄窗口保留预期的纵向滚动。
