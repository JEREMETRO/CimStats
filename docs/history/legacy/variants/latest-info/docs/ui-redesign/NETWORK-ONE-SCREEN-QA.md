## 取证环境和判定方法

- 用桌面程序 `MainWindow.start_parse()` 分别实际加载 `D:\test\CIM2_SaveStats\data\望春市6.save`、`D:\test\CIM2_SaveStats\data\quicksave.76561198362520556-76561198845688243.save`。解析中间文件、探针及导出写入临时目录；记录原 `.save` 前后 SHA-256。演示或合成数据可用于超过两家公司的压力检查，不能代替以下真实存档截图。
- 每个硬验收场景按上表**五组物理分辨率＋系统缩放**逐组抓完整窗口截图，记录原生/模拟来源及屏幕、窗口和视口实测值。加载、模式切换、Pivot、筛选/摘要收展及图形淡入动画必须结束，QtCharts 离屏缓存必须刷新后再抓图。
- 每张证据另外标注数据来源：**本次真实 `.save` 解析**或**沿用已解析缓存的界面重排**。缓存矩阵只能证明当前数据下的布局，不能宣称每一环境都重新完成了真实解析。实现方已提供 Windows 175% 原生截图及其余 DPI 模拟/缓存初测，独立 QA 仍须分别核实并保留原始来源，不将实现方自测写成独立通过。
- 对公司页 `StatisticsPage.scroll`、网络页 `StatisticsPage.network_scroll`，读取水平和垂直 `scrollBar().maximum()`，**两轴都必须等于 0**。即使水平滚动条被设为隐藏，也必须检查 `maximum()`；隐藏滚动条不算通过。
- 逐项记录每个 KPI 卡和图卡相对 `scroll.viewport()` 的矩形。所有图卡应可见且边界完全落在视口内：`left/top >= 0`、`right < viewport.width()`、`bottom < viewport.height()`。检查卡内标题、图形、轴刻度、图例、切换按钮、全屏按钮、单位均可读，无文字互压、截断或卡片重叠。只拼接长图、手工向下滚动、多张分段截图、隐藏卡片、裁切内容、分页或折叠都不能代替一屏证据。
- 报告给出每场景的 `物理屏幕/系统缩放/Qt DPR/逻辑 DPI/availableGeometry/窗口 frame/客户区/视口、横纵最大滚动值、KPI 数、图卡数、最下方图卡 bottom 与视口 bottom`，并附原尺寸整窗截图。任何必验数值不符合即判失败，不因“看上去差不多”改判。

## 整页高度预算与导航

- 先量出五组环境中应用最大化后的实际客户区及统计页可用高度，再记录标题/Pivot、筛选、摘要、图卡四部分的实际高度和间距。布局调整应把高度预算分配给整页；不能只压低图表绘图区来凑 `scroll maximum=0`。
- 常用宽窗优先让“统计数据”标题与“公司数据／网络数据／城市数据”Pivot 同行，右侧保留当前文件信息和“打开存档”。标题字与图标、Pivot 字号可适当收紧（例如标题 22–24、标签 13–14），以最终原尺寸截图的清晰度和点击面积为准，不把这些示例数字当唯一实现。
- 筛选区、摘要区、图卡标题区的垂直内边距和区间距可以压缩，筛选控件合理同行组织。检查所有功能入口、数值单位、图例、坐标轴与悬浮操作仍能辨认；禁止以文字截断或图形过小换取零滚动。
- 较窄窗口允许标题/Pivot、筛选项合理换行。逐张检查当前标签文字、蓝色下划线、键盘焦点及按钮点击目标均清楚且同位，标签不能被裁切。切换至城市页后，Pivot 选中态与内容仍正确；城市业务数据和绘图保持原状。
- 截图判读同时检查整页比例：顶部空间是否仍过大、图卡是否被压扁、轴与图例是否退化。即使滚动最大值和边界均合格，整页可读性不合格也不能判通过。
- 自适应必须双向工作：根据真实视口宽高和图卡数量分配网格列数、行高、摘要尺寸与留白。空间不足时先收紧页头/Pivot/筛选，再给图形保留可读高度；空间增大时优先扩大**有效绘图区**，适度增加卡片内边距、标题字号与间距，并设上下限，不能把固定矮卡堆在顶部、下方留下大片无必要空白，也不能让所有控件无上限同比放大。
- 五组环境都记录图卡有效绘图区和视口底部未使用高度（逻辑像素及比例），用整窗截图判断是否协调。高物理分辨率不必然有较大逻辑视口；仅 `scroll maximum=0` 不够，图幅、字号与留白比例也应合理。
- 在同一已加载真实存档及固定缩放环境内连续拖动窗口，跨越各组实际逻辑视口附近的宽高临界点并反向缩回，记录图卡列数、最远边界、滚动最大值与截图。图卡数和数据值不得丢失，布局不能在阈值附近来回跳动、循环重排、出现短暂溢出或不可恢复的空白。缩放比例改变时另起独立环境记录，不能以改变窗口像素尺寸代替。

## 其他模式的紧凑验收

公司页的多公司对比、同期对比，以及网络页的多公司对比、单公司同期，均按五组显示环境记录实际一屏能力。逐模式、逐收展状态记录横纵滚动最大值、KPI/图卡数量及最远边界，并打开截图检查轴、图例、切换按钮、单位。若模式确实无法一屏，报告必须列出具体物理环境、实际视口、超出逻辑像素、受影响图卡与可读性证据；不能笼统写“整体通过”。其数据源、同期日期、公司身份和同量程规则继续按既有合同复验。

所有网络模式中的双选图形按钮均应固定在对应图卡的标题同行，包括同期模式；切换模式后不能再次掉入第二行或挤压长标题。逐模式打开截图核对，而非仅用总体模式推断。

## 2026-09-30 交互和加载流程追加验收

- 筛选操作区把“确定”和“导出”相邻组成一组，提醒设置位于该组之前。同期筛选在宽视口分为左右两栏：左侧为公司及时间范围，右侧为模式、粒度及跨期对比；窄视口顺序换行，不压盖字段、隐藏自定义区间入口或改变已选择条件。点击“确定”收起筛选后，紧凑摘要准确列出公司、时间范围、粒度、模式与跨期条件；重新展开并修改、再次收起时内容实时更新，导出始终使用当前条件。
- 筛选展开入口改为图标按钮，检查 tooltip、无障碍名称、至少 32px 点击区域、键盘焦点及触发动作。筛选收展动画结束后按钮恢复可用，视口重算、图卡边界、滚动范围和数据值均正确；过程中不出现长期遮挡、空白或无法恢复的布局。
- 按最新样式检查筛选按钮 36px 点击目标，以及“导出报表”“打开存档”各 144px 宽度。与相邻操作和页头的间距、完整文字、焦点与窄窗换行均须可读可点；不能因为固定尺寸造成遮挡或溢出。
- 公司与网络摘要均有明确的最小化/向下展开入口。双公司在同页点击任一家摘要入口时，两家摘要同步折叠/展开，左右图卡保持对齐。折叠只隐藏摘要内容并把空间分配给有效绘图区，摘要对象、KPI 数值、公司身份、筛选和图卡不得销毁或重算成其他口径；恢复后数据与选择不变。网络总体的紧凑摘要头仍清楚表示当前总体。**核心默认/总体的一屏硬门槛始终先在筛选和摘要均展开的默认状态判定**，再另记折叠后的视口、滚动值和有效图幅，不能混报。
- 公司摘要为独立白色卡片，与图表卡处于同级布局；检查两个卡片各自的边界、间距、背景和收展后图表扩展。满意度下拉位于 KPI 标题区域，字体、字号、颜色与其他 KPI 标题一致；28px 标题行的文字、图标与操作居中且不互压、不裁切，鼠标和键盘均可操作。单/双公司、筛选与摘要展开/折叠、五组 DPI 环境分别检查。
- 顶部存档信息显示真实模拟日期的星期、实际公司总数及单人/多人状态，核对单人 2013-04-18（星期四）、双人 2013-04-10（星期三）及各自公司数 1/2。文件名可省略显示但 hover/focus 提示必须给出完整名称。底部状态栏及多余的顶部常驻 status 行均不占布局，加载成功后不出现“解析完成：N 家公司、M 条线路”之类额外完成文案；进行中的阶段/故障信息仍须在遮罩或必要的临时提示中可见，失败不能静默。
- Windows 原生窗口按用户最新偏好使用普通浅色 Mica（DWM type 2），在首次显示、隐藏后再显示、切换页面与缩放后保持正确背景，不闪黑或整窗黑屏。`showEvent` 重施材质后检查首次帧及稳定帧；其他平台或无材质支持环境检查清楚可读的回退背景。此前 Mica Alt（type 4）截图仅为历史对比，不能作为最终材质通过证据，也不能推断所有 DPI/平台均通过。

- 加载完成门槛分别核对两份 snapshot、查询定时器与工作线程均已就绪，统计页图表完成首次可交互绘制；不能在解析子进程退出时提前隐藏遮罩。制造解析失败、用户取消、超时与旧任务晚返回，确认 token 失效、遮罩释放、操作恢复，且新的存档结果不被覆盖。捕获内部 `CIM2_PROGRESS` JSON 时仅用于诊断，界面不得直接显示原始协议文本或把阶段权重冒充实际进度。

## 加载性能优化独立验收

- 待性能优化稳定提交后，按相同机器、相同真实存档、相同输出目录隔离策略分别测量优化前后从用户启动加载到结果可用的**端到端**时间，冷启动与热缓存分开记录，每个场景重复运行并列出原始值和波动。记录文件大小、解析子进程峰值 RSS、系统内存占用和样本环境；不以后台单一函数的耗时替代用户实际等待时间。
- 对单人、双人及其他可用真实存档逐项复核生成结果一致性，至少比较公司身份、日期、关键汇总值、图表数据和输出文件。中途取消、连续打开不同存档以及较早任务晚返回时，检查旧结果被拒收、遮罩状态正确且不会覆盖新结果。原始 `.save` 与起始时的探针 DLL 哈希保持不变。
- 优化会改变阶段耗时和内存曲线，旧时间/RSS 预测参数不得继续用于产品进度。核对优化后每个实际阶段及 `done/total` 事件与界面进度轨迹的对应关系、固定区间边界和完成门槛；没有细分事件的阶段允许停留。若研究报告继续拟合时间/RSS 模型，须另列样本分层、留出误差与适用范围，并与产品进度实现明确隔离。

进度需求沿革：此前要求用大小、耗时和内存拟合并持续显示“预计进度”；**最新用户要求已取代该产品规则**，改由解析器实际进展驱动。旧采样可保留作研究与性能基线，不能作为本轮界面进度通过的依据。

## 配色与控件硬门槛

- 公司与网络页的柱形、分类横条、堆积柱、饼图主体使用与亮蓝折线同一视觉亮度层级的**鲜明、可辨类别色**。不能继续呈灰蓝、土黄、低对比暗淡效果；六个人群类别需要不同色相和足够明度差，不能靠同一色深浅或随机取色。先看参考图对应旧问题，再看新整窗及单卡截图。
- 柱形和饼图扇区主体保持充分不透明；**只有面积填充**可降低透明度。核查实际系列画刷与截图内部实色像素，勿把抗锯齿边缘或 180 毫秒淡入过渡帧当最终颜色。
- 同一公司在 KPI 所属图标、折线、点、时间柱、图例、悬浮标记中颜色稳定；同一类别跨折线、堆积、分类横条、饼图、图例和 tooltip 色点保持同源。普通功能图标使用统一中性色或 UI 蓝；不把未定义的红/绿含义标成好坏。
- 显示按钮使用“趋势／分布／比例”；时间柱仍属于趋势、分类条形属于分布、饼图属于比例。切换不改变数据含义；数值与单位同排。窄卡及压缩后的坐标轴、中文图例与按钮仍能辨认。
- 按用户追加要求，移除所有图卡标题前的图标，适当减弱 KPI 内切换按钮的选中态；确认标题和按钮仍清楚可辨，现有公司/类别色身份不受影响。
- 在需要滚动的比较/同期模式提供用户主动收起、重新展开筛选区的入口。分别测量并标明筛选**展开**与**收起**时的视口和滚动值；不能把收起结果写成展开状态通过。收起后图卡有效绘图区仍须可读，切换条件和导出状态保持，重新展开后筛选值、焦点与布局恢复正确。核心公司默认/网络总体的既有一屏硬门槛仍以筛选展开状态验收。
- 覆盖式滚动条须保留真实可滚动范围与滚轮/触摸板/触控操作；所有 `maximum=0` 硬门槛仍读取实际滚动范围，不能靠覆盖外观隐藏溢出。页面或图卡获得焦点时方向键能滚动有溢出的内容，ComboBox、日期和图形切换按钮获得焦点时则保留其自身方向键操作，不被页面抢走。
- 图表模式按钮与 KPI 内切换按钮采用一致的紧凑、弱强调样式；选中、悬停、键盘焦点和禁用状态仍各自可辨，不因减弱高亮而失去当前选项提示。
- 城市页不改变统计数据、默认色板或按钮文案。只做共享控件变更的退化检查，不能借公司/网络色板默认值改写城市页。
