- 确定/导出组成相邻操作组，提醒设置位于组前。

- 删除底部状态栏，必要消息移到内容顶部。中心遮罩接入现有解析线程；10/70/82/92为阶段权重而非读取百分比，当前阶段/日志与“预计进度”分开。进行中最高99%，图表真正就绪才收起遮罩，失败/取消使在途任务失效。预测函数及扩样验证由性能线程维护。

## 替换后的硬验收矩阵

用户新增：物理屏幕/系统缩放为2880×1920/200%、1920×1080/100%、2560×1440/125%、3840×2160/175%、2560×1600/150%。理论逻辑尺寸分别约1440×960、1920×1080、2048×1152、2194×1234、1707×1067，以Qt实际DPR与geometry为准。不得用物理尺寸resize或PNG放大代替高DPI。当前环境不更改全局显示设置，用每组合独立Qt高DPI模拟进程；明确记录模拟屏幕/availableGeometry、客户区/视口、图片物理像素。原生多分辨率系统设置与实体鼠标命中未实测。

## 内存曲线与预计进度补充

用户要求实测多个存档的内存时变曲线，给出基于存档大小的预测函数。实际可用5个存档约23–33 MiB。串行每档两次采样，100ms间隔记录桌面RSS、解析子进程树RSS、系统已用/可用内存、CPU耗时与阶段；原件哈希及测试前既有probe字节保全。模型必须独立重复/留档验证，报告文件大小适用范围和误差；内存峰值会回落，禁止RSS/大小直接当百分比。估计输出需明确“预计”、单调且真正完成前低于100%。系统内存只能做背景负载诊断。是否上线依据测量结果决定。

## 用户追加视觉修正

实际折叠范围仍是数据摘要，但此前公司摘要和图表同在一个白色大框，用户指出视觉上像整体折叠。调整为独立公司摘要卡，标题/折叠入口仅在该卡内，图表卡为其外部兄弟元素。满意度下拉直接替换满意度 KPI 卡片标题，不占公司标题行或额外行。各公司 KPI 统一 28px 标题行，18px 图标与标题/下拉同一行垂直居中。网络/城市滚动内容默认 autoFillBackground 导致灰色条带，清除所有滚动视口/host底色并透出共享基底。数据/图表口径不改变。

原生 Mica 黑屏已复现：仅构造期设置后，窗口 native HWND/backing surface 初始化使背景变黑；在 showEvent 后重新应用可恢复。正式窗口已加入该生命周期处理。用户随后指出普通 Mica 看似纯色，原生激活窗口对比 type2/type4：普通 type2 底色几乎均为 RGB(242,243,244)，Mica Alt type4 在多个背景点出现 RGB(213,219,227) 到 (210,219,236) 的墙纸色变化，因此正式采用 Mica Alt。透明效果开启，非远程会话；截图必须确认应用激活，不把 inactive 纯色回退当渐变证据。`qa_native_mica.py` 使用缓存真实存档、临时置顶测试窗、前台窗口身份校验及 DWM 属性验证，正式原生截图在 `refinement-correction-evidence/native-mica-multi-company.png`。此环境物理3840×2160/系统175%，Qt DPR1.75，1440×960逻辑窗口，截图2520×1680；其余5组矩阵仍明确为Qt离屏模拟。
