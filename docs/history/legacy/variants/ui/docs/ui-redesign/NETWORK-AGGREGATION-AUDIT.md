# 网络总体取数复核

2026-09-29 按用户更正复核。以下是数据来源和计算口径；这些实现说明不放在主界面。

## 原始字段到页面

| 页面指标 | HistoryData `m_name` | 原始分组 | 汇总 |
| --- | --- | --- | --- |
| 线路数 | `linecount` | 制式 | 同一有效期末时点求和 |
| 站点数 | `stopcount` | 制式 | 同一有效期末时点求和 |
| 车库数 | `depotcount` | 制式 | 同一有效期末时点求和 |
| 平均运行车辆数 | `vehicles-running` | 制式 | 同一观测小时合成后按小时加权 |
| 覆盖率 | `coverage` | 每家公司 `m_baseGroup`（“任意”）及群体分类 | 单家公司直接使用“任意”的值和分母；多家公司联合覆盖率暂无可靠来源 |
| 客流 | `transport-by-type` | 制式 | 所选公司各制式小时计数求和 |
| 分群体客流 | `transport-by-group` | 群体 | 客流的另一种分解，不再次加入总客流 |
| 分区出行量 | `trip-types` | single-line、one-zone 等 | 所选公司各类别小时计数求和 |
| 平均换乘系数 | 由上两项派生 | 所有类别 | **总客流 ÷ 总分区出行量**；不平均公司比值或小时比值 |

`extract_runtime_data.py:history_rows` 将 `m_company` 对应到玩家 ID。coverage 的 `m_baseGroup` 单独标为“任意／总计”，`m_tempGroups` 标为“分类”；两者保留来源，查询总计优先使用总组，分类图只使用分类，不重复相加。旧 CSV 没有总组时仍按分类计算单家公司总计。原始总组的当前槽 `m_value/m_divider` 在两份样本中为 0/0，而当前分类有值；仅在总组这两个字段均为零且完整分类值存在时，用该公司当前分类合成一次，并标记来源。`HistoryStore`/`build_dashboard` 仅查询所选公司；`network_model` 在同一快照上生成摘要和图表，XLSX 网络摘要沿用该快照。

## 真实导出复算

只读反序列化 `data/quicksave.76561198362520556-76561198845688243.save`：coverage 有两条 `HistoryData`，各归属一家玩家公司，没有无公司归属的 coverage。两家公司 `m_baseGroup` 历史有效槽 0–230 均与同刻六个 `m_tempGroups` 的值、分母之和相同；共核对 462 个历史总组时点。当前槽 231 的原始总组字段为 0/0，分类合计分别为 11,817/17,401 和 12,803/17,401。新解析后全部 464 个公司时点的“任意”与分类合计一致。

单人存档 `data/望春市6.save` 也有公司归属的 coverage 总组；历史槽 0–422 与六分类合计相同。当前槽 423 的总组为 0/0，分类合计 9,895/12,593；新解析后 424 个时点一致。上述数据证明“任意”是**每家公司**的历史总组。多人存档两家公司的分母在同一时刻重复，不能把两个总组的分子、分母相加并称为跨公司联合覆盖率。

页面据此在多公司总体模式省去 coverage 摘要和图卡，不留下占位；单公司总体、公司对比和同期模式继续使用各公司的“任意”总组。公司对比的覆盖率曲线每家公司一条，保留完整筛选时间范围，分类观测不会再出现为六条公司曲线。

旧格式原始历史导出 `exports/CIM2_城市历史指标_完整_quicksave.76561198362520556-76561198845688243_运行时.csv` 有 51,282 行，只含分类且只有公司名称。`load_session` 用唯一名称回填稳定公司 ID。`transport-by-type`、`transport-by-group`、`trip-types` 均有公司归属，`trip-number` 是无公司归属的城市出行记录。**换乘系数分母取 `trip-types`，不是城市 `trip-number`。**

选该样本两家公司、2013-04-09 00:00 至 2013-04-10 00:00 的 24 小时：

- 平均换乘系数：分制式总客流 1,171,479，分区出行量 443,702，模型结果 `2.640238268026738666943128496`。
- 站点数：两公司有效期末分类合计 3,741。

以上客流与系数数字来自旧 CSV 的整段窗口复算；当前网络摘要的平均值、比例值改取筛选结束前最后一个日历日，故摘要值与旧整段复算不应混同。在新解析样本、2013-04-10 00:00 至 04-11 00:00 的最后一天，模型给两家公司各自 coverage `62.21764787810262444768815889%`、`65.70693173979463705065202682%`；网络总体 coverage 保持缺失。无有效同窗数据时仍显示缺失；瞬时最大运行车辆数没有历史来源，保持不可用。

自动复算用例在 `src/test_statistics_model.py` 验证总组优先和分类不重复，`src/test_history_contract.py` 验证当前槽回退和真实零分母，`src/test_network_model.py` 验证所选子集、最后日历日、站点同期末总数、系数零分母公司及缺测。

数量折线保留完整时间范围，每家公司一条总数曲线；分类横条使用各分类在各自周期结束前最后一个观测值。同一公司分类若停在不同观测时刻，较早的横条标为数据不完整，并在提示中显示实际观测时间。
