# 统计界面改版：双计划执行、Git 分支与验收方案

## 1. 两个计划共同生效

实施时严格同时遵循：

- **P1：《统计数据页面与应用外框改版计划》**——完整功能、数据口径、交互及交付要求。
- **P2：《统计数据改版、并行实施与验收计划》**——补充文案限制、整数坐标轴、并行分工及严格 UI 验收。
- **本次修订**——补充模型上限、Git 分支和计划一致性检查。

**后续计划未重复的内容不代表取消。** 只有用户明确提出的新要求覆盖旧约定；无法同时满足的冲突在当前会话提出，不由实施会话自行删减。

实施开始时，将 P1、P2 原文完整保存，并建立逐项需求对照表，记录“来源、负责任务、实现位置、验证证据、完成状态”。每个任务必须阅读两份完整计划及本次修订，不能只凭任务摘要实现。

明确覆盖关系：

- 应用使用侧边汉堡菜单，不采用此前讨论的顶部导航。
- 恢复平均换乘系数，不执行早期取消该指标的建议。
- 分群体、分制式、分区分别支持四种视图。
- 原计划中的解释性说明不得自动展示，遵循后来增加的文案审批要求。
- 所有子任务思考深度不超过 **medium**。

## 2. 必须完整保留的产品要求

### 外框与公共操作

- 保留 PySide6／Qt，采用浅色 WinUI／Fluent 风格；系统标题栏、可折叠侧栏，三个入口为公司概览、线路查询、统计数据。
- 其他页面保留功能与内容，只适配公共外框和控件。
- 单存档、公司多选；默认全部公司。公司数据分别对比，城市数据只显示一次。
- 默认最近七个完整模拟日，按日统计，与此前七日比较。
- 保留小时／日／周／月、时间范围，以及关闭对比、上一等长区间、上周同期、上月同期、自定义对比。
- 历史不足不补零、不生成无依据的提醒。后台查询可取消，旧请求不能覆盖新存档或新筛选结果。
- 保存侧栏状态、指标和图表选择；公司颜色稳定。
- 移除聚合明细、原始小时追溯、全部原始字段入口，保留数值悬浮提示。

### 四看板

| 看板 | 必须实现 |
|---|---|
| 公司 | 现金流、公司价值、月票使用率、满意度、声誉、受欢迎程度；满意度切换速度／费用／质量；最多三个指标对比，不同单位使用时间轴对齐的小图 |
| 服务 | 线路数、分制式站点数、车库数、平均运行车辆数、覆盖率，以及线路趋势、站点分类 |
| 客流 | 分群体、分制式、分区三个独立区域，各自切换总统计数据／条形图／折线图／饼图；换乘系数卡片和趋势 |
| 城市 | 人口、经济增长／利率、能源价格、出行量、出行方式占比、道路／轨道交通密度 |

- 公司现金流、城市出行量默认柱状趋势，其余趋势默认折线。
- 客流三个区域默认依次为折线、饼图、条形图，并独立保存选择。
- 总统计数据只显示总量大数字；条形图显示类别累计量，折线图显示分周期趋势，饼图显示类别占比。
- 多公司构成分别展示；图例显隐不改变统计总量和系数。
- 城市出行方式采用条形图，不强制归一为 100%。
- 站点不跨制式直接合计为去重站点数；平均运行车辆数不当作车辆拥有量。

### 数据口径、提醒与导出

- 分群体和分制式是同一批乘车人次的不同分类，不能相加。
- 分区采用单线、一区、二区、三区、四区等游戏类别，统计出行量，不替换为城区名称。
- 平均换乘系数＝同公司、同时间范围的分制式客流合计÷分区出行量合计；汇总分子除以汇总分母，不平均小时系数。
- 系数显示两位小数，零分母显示“—”；不裁剪异常值，不将下降自动判断为改善。
- GDP 替换为已有经济指标；能源沿用原始值口径。
- 提醒覆盖四看板，沿用现有阈值，支持开关、阈值设置、单条／全部已读及重启保存。
- 提醒身份关联存档、公司、指标和比较窗口，数据变化产生新提醒。
- PNG 输出完整看板；XLSX 输出筛选信息、四看板统计结果、单位、时间及完整度。两者与页面复用同一结果。
- 保留其他页面既有 XLSX 导出；不增加地图等新功能页面。

## 3. 文案、坐标轴和布局硬约束

### 文案

未经用户同意，不增加说明、备注、使用建议、数据原理或开发信息，包括页面、悬浮提示、信息图标和弹窗。

功能名称、指标、单位、数值、图例、按钮使用统一清单。数值悬浮提示只包含对象、时间、指标、数值和单位。缺失值显示“—”。

必要的新说明须先提交具体文字、位置与原因，经用户同意后才能加入；技术依据保留在开发文档。

### 坐标轴

- 非负数值轴从 0 起；含负数时保留 0 和全部负值。
- 刻度为整数，间隔采用 `1、2、5 × 10ⁿ` 的整步长，上下限为步长整数倍。
- 大数可使用千／万单位，但换算后的刻度仍须为整数；小量级使用 0、1、2……。
- 整数要求不改变实际数据精度，系数等仍保留小数。
- 优先显示 4—7 个刻度；全零数据保留有效范围。
- 时间轴、分类轴按自身含义展示；对比小图共用单位与量程。

### 自适应布局

- 内容宽度 ≥1400：两列四看板＋右侧提醒。
- 1000—1399：两列看板，提醒置后。
- 更窄：单列纵向滚动，侧栏默认折叠。
- 页面边距默认 20、窄窗 12；卡片内边距 16、区域间距 16、紧凑控件间距至少 8，均为逻辑像素。
- 空间不足通过重排、滚动解决，不无限压缩文字和控件。

## 4. Git 分支与并行任务

已确认当前主仓库位于 `main`，提交为 `ff7618c`；另有正在使用的 `feature/statistics-center` worktree。现有图片及两个未跟踪探针文件保持原样，不混入代码提交，不复用旧统计分支。

### 分支安排

- 从实施开始时核实的 `main` 基线创建 **`feature/stats-ui-integration`**，使用独立 worktree，作为主会话集成分支。
- 主会话先提交两份计划、需求对照表、共享接口约定和文件归属。
- A／B／C 从同一接口基线创建：
  - `feature/stats-ui-data`
  - `feature/stats-ui-shell`
  - `feature/stats-ui-charts`
- D 在接口和基础组件完成集成后创建 `feature/stats-ui-export-alerts`。
- E／F 针对固定的集成提交开展检查，不修改生产代码。
- 各实施分支在独立 worktree 工作，按职责提交；主会话审查通过后合入集成分支。所有集成均由主会话负责。
- 禁止重置用户分支、改写已有历史、强推或覆盖正式包。当前未配置远程，不安排推送。
- 最终从同一个已验证集成提交构建候选包，正式发布另按项目流程执行。

### 模型与分包

| 包 | 模型／思考深度 | 职责 |
|---|---|---|
| A | GPT-6 Astra／medium | 统计结果层、聚合、换乘系数、完整度与数据测试 |
| B | GPT-6 Sol／medium | 应用外框、浅色主题、工具区、四看板布局 |
| C | GPT-6 Sol／medium | 通用图表、整数轴、客流四视图、图例与配色 |
| D | GPT-6 Sol／medium | 提醒持久化、PNG／XLSX 导出 |
| E | GPT-6 Luna／medium | 执行尺寸矩阵、收集截图、文案清单和导出检查 |
| F | GPT-6 Astra／medium | 独立审查计算、异步状态、数据一致性和边界问题 |

最多三个实施任务并行。A／B／C 首批执行，D 待依赖稳定后执行，E／F 检查稳定的集成版本。主会话负责共享入口、接口调整、合并和最终判断。

每个任务必须返回提交标识、需求覆盖情况、测试结果、相关截图及未解决问题。不得擅自改动其他任务文件、增删功能或添加页面说明。
