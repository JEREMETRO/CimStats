# 统计数据改版、并行实施与验收计划

## 1. 页面范围与文案约束

保留 Qt，采用浅色 WinUI／Fluent 风格和可折叠侧边汉堡菜单。菜单包含“公司概览、线路查询、统计数据”；其他页面保留现有功能。

**未经你允许，不向页面增加说明、备注或解释性文案。**

- 允许展示已确定的功能名称、指标名称、单位、数值、图例和操作按钮。
- 禁止自行增加计算原理、数据来源解释、开发备注、风险提示、使用建议及装饰性副标题；包括悬浮提示、信息图标、弹窗中的此类文字。
- 悬浮提示只展示对象、时间、指标、数值和单位。
- 原计划中的换乘口径说明、数据限制说明等，不直接进入页面。详细依据保留在开发文档。
- 如果确有必要新增说明，先在当前会话提交**具体文字、出现位置和必要原因**，得到你同意后再加入。
- 缺失或不可计算的数字使用“—”，不得补零或编造结果；沿用必要的现有加载、失败状态，不擅自扩写解释。
- 各任务共用集中管理的文案清单，主会话逐项检查新增可见字符串。

## 2. 看板、交互与坐标轴

### 公共布局与数据选择

- 单存档、公司多选；多家公司分别对比，城市数据只展示一次。
- 默认最近七个完整模拟日，按日汇总，与此前七日比较；保留小时／日／周／月及自定义时间、对比范围。
- 内容宽度 ≥1400：两列四看板＋右侧提醒；1000—1399：两列看板、提醒置后；更窄：单列纵向滚动。
- 保存侧栏状态、指标和图表选择；不再提供聚合明细、原始小时追溯、全部原始字段入口。

### 四看板

| 看板 | 内容与交互 |
|---|---|
| 公司 | 现金流、公司价值、月票使用率、满意度、声誉、受欢迎程度；满意度支持速度／费用／质量；最多三个指标对比，不同单位使用对齐的小图 |
| 服务 | 线路数、分制式站点数、车库数、平均运行车辆数、覆盖率，以及线路趋势、站点分类 |
| 客流 | 分群体、分制式、分区三个独立区域，各自切换总统计数据／条形图／折线图／饼图，下方展示平均换乘系数和趋势 |
| 城市 | 人口、经济增长／利率、能源价格、出行量、出行方式占比、道路／轨道交通密度 |

客流默认分别使用折线图、饼图、条形图。“总统计数据”仅显示总量大数字；条形图比较类别累计量，折线图展示时间趋势，饼图展示类别占比。多家公司分别显示构成。

分群体与分制式为同一批乘车人次的不同分类，不相加。分区为单线、一区、二区、三区、四区等出行类别。

**平均换乘系数＝同公司、同时间范围的分制式客流合计÷分区出行量合计。** 按总分子／总分母计算，不平均小时系数；分母为零显示“—”。卡片保留两位小数。

### 坐标轴硬性规则

- 所有柱状、条形、折线图共用一套轴范围算法。
- **非负数值轴必须从 0 起。** 含负值时包含 0 和全部负值，按整步长向外扩展；不得截断负数。
- **刻度标签必须为整数，间隔采用 `1、2、5 × 10ⁿ` 的整步长**，例如 0、100、200，或 0、2000、4000。
- 大数可统一使用“千／万”等轴单位，但换算后刻度仍为整数；禁止出现 0.5 万、1.5 万等刻度。
- 小量级指标使用 0、1、2……等整数刻度，实际曲线、悬浮值和导出保留真实小数。
- 上下限为步长整数倍，非退化范围优先显示 4—7 个刻度；零值数据也保留有效轴范围。
- 时间轴按小时／日期等显示，分类轴按类别显示，不机械套用数值轴的零起点。
- 对比小图共用单位与数值范围；禁止自动裁窄纵轴夸大变化。

## 3. 实现边界与并行分包

由主会话先确定共享接口、主题尺寸、文案清单和文件归属，再分派独立任务会话。每个会话使用独立 worktree，最多三个实施会话同时运行。

接口统一为：筛选状态、看板查询结果、图表序列、轴规格和导出快照。结果保留公司标识、指标、单位、时间、当前／对比值及完整度；界面与导出共用结果，不重复计算业务口径。

| 任务包 | 模型与思考深度 | 独立职责 |
|---|---|---|
| A：统计数据与换乘系数 | GPT-6 Astra · high | 批量查询、周期聚合、系数、完整度、过期请求处理及数据测试 |
| B：应用外框与自适应布局 | GPT-6 Sol · high | 汉堡侧栏、浅色主题、公共工具区、四看板容器和窗口重排 |
| C：图表与客流交互 | GPT-6 Sol · high | 通用图表、整数轴算法、三个客流区域的四视图切换、公司颜色与图例 |
| D：提醒与导出 | GPT-6 Sol · medium | 已读状态持久化、PNG 完整看板导出、XLSX 数值导出 |
| E：验收辅助检查 | GPT-6 Luna · medium | 执行既定尺寸矩阵、收集截图、检查文案清单和导出文件，不决定业务口径 |
| F：独立代码复核 | GPT-6 Astra · xhigh | 复核统计计算、异步状态、数据一致性和边界缺陷，只提交审查意见 |

各包显式指定模型与思考深度，不依赖默认继承；思考深度属于可配置参数，见 [OpenAI 参数说明](https://developers.openai.com/api/docs/guides/reasoning)。上述分配是针对本项目的安排。

执行顺序：

1. 主会话固定接口与归属，A／B／C 并行。
2. 主会话逐包审查、集成；共享入口由主会话统一修改。
3. 接口稳定后启动 D；稳定集成版本交由 E／F 检查。
4. 缺陷退回原任务会话修复，主会话重新验证。
5. 各会话不得自行发布、修改他包文件、增加页面说明或改变统计口径。

每包必须返回：提交标识、改动说明、验证命令与结果、相关截图及未解决问题。**任务返回“完成”不等于验收通过。**

## 4. 提醒、导出与数据验证

- 提醒支持单条／全部已读及重启保留；身份关联存档内容、公司、指标和比较窗口。
- 仅完整、可比较的数据生成变化提醒；换乘系数升降不自动解释成好坏。
- PNG 导出完整看板；XLSX 输出筛选信息和四看板统计结果，保留单位、时间及完整度，不提供原始小时追溯表。
- 验证分群体／分制式合计一致；已核查样本对应历史范围的系数约为 3.1513、2.6771、2.4776。
- 覆盖零分母、缺小时、未完成周期、负现金流、无比较期、同名公司和快速切换筛选。
- 轴测试覆盖全零、小数、小量级、百／千／万量级、正负混合及公司对比共用量程。

## 5. 主会话最终 UI 验收

**我负责最终代码与 UI 验收，不只依赖子会话报告或自动测试。**

- 检查客户区尺寸：1920×1080、1600×900、1366×768、1024×768、920×680；同时检查布局断点前后和连续拖动缩放。
- 在 100%、125%、150%、200% 显示缩放下检查布局；按实际可用客户区判断重排。
- 覆盖侧栏展开／折叠、长公司名、多公司、长图例、大数、空数据、全部图表模式和展开的菜单。
- 逐项检查：文字截断、图例碰撞、轴标签重叠、按钮遮挡、弹出层越界、滚动不可达、边距过窄及多余空白。
- 默认页面边距 20、窄窗 12；卡片内边距 16，区域间距 16，紧凑控件间距至少 8，均使用 Qt 逻辑像素。空间不足时重排或滚动，不通过无限压缩解决。
- 结合控件边界检查和实际渲染截图逐尺寸审阅；修复后复查受影响尺寸与相邻断点。
- 全量回归、真实存档界面和候选程序检查全部通过后交付。存在遮挡、碰撞、不可达操作或未经批准的说明文案时，不标记完成。
