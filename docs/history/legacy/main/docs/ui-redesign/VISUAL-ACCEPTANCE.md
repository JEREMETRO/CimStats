# 返回前必须执行的视觉与需求自查

2026-09-29用户新增硬要求。本文件优先于早期计划中与之冲突的控件选择。每个子会话在最终回复或阶段交付前必须自查，不能以单元测试通过代替视觉验收。

更具体的控件效果、布局和实现方式见[CONTROL-SPEC.md](CONTROL-SPEC.md)。其中共享FluentSegmentedControl（现成TogglePushButton互斥组合）覆盖下文早期泛指SegmentedWidget的选型，以达到原图蓝底白字选中效果。

## 当前已发现的问题及必须修正的控件

- 统计页当前使用QTabBar，而原图为图标+文字+蓝色底线的Fluent分节导航。必须替换为qfluentwidgets.Pivot，使用company/network/city路由键，配FluentIcon，约40高、18图标、14–16文字、选中蓝色细底线。禁止可见的原生QTabBar/QTabWidget页签和灰色凸起页签外框。
- 三分析模式必须常显共享FluentSegmentedControl（按CONTROL-SPEC.md组合Fluent TogglePushButton），约36高，三个可直接点击的按钮；原图激活项蓝底白字，未选浅底深字，有hover/pressed/disabled/keyboard focus。不得用analysis_mode_combo下拉或默认SegmentedWidget选中外观替代。
- 所有“图形类型/图表样式”切换必须使用具名分段按钮，如折线/面积、趋势/制式分布、时间柱状/构成饼图。禁止模式ComboBox，不能用只有图标没有清楚含义的按钮。网络每卡自己的切换仍独立保存。
- 摘要车库/站点、平均/最大、客流/出行量也是卡片标题内的紧凑分段切换，不加三行全局控件。
- 时间范围、时间粒度、比较周期和满意度维度可保留真正的Fluent ComboBox；公司多选用带选中标签的Fluent下拉。指标选择不是图形模式，可用图卡标题旁Fluent菜单；禁止在页面堆出四个“图表1/2/3/4”大下拉框作为常态工具栏，具体图位指标选择应移到各自图卡头部。
- 图卡全屏使用Fluent TransparentToolButton（缩窄时保留tooltip/辅助名称），图例使用Fluent可切换控件或同风格轻量图例；不能用显著默认Qt工具按钮边框。Qt底层布局/绘图可继续使用，但可见控件必须完整采用共享样式。
- 图卡头部对齐、标题约16半粗体、指标线性图标约20–22，图例小色点+12号文字，图卡白底轻边8圆角，绘图区无独立框。水平网格低对比，坐标轴/字色比数据线轻；不能仅改画布颜色就称Fluent完成。
- KPI图标、标签、数值、单位形成参考图的清晰层级；不得只把裸QLabel数值置于普通QFrame内就当视觉完成。最终可以用QLabel/QFrame作为绘制基础，但需要明确共享字体、边框、圆角、状态与实际截图证明。

以上控件类在当前安装的PySide6-Fluent-Widgets中已核对存在。优先基于其公开接口/自定义样式调整选中蓝色，不重新发明另一套控件系统。修正不能破坏三模式语义、四图六指标/网络八九图及数据边界。

## 每次阶段交付/最终回复前的步骤

1. 重新打开与本阶段有关的原图，读README、DESIGN、VISUAL-CONTRACT、NETWORK-PLAN及本文件最新修订。列出该阶段关键要素，不按印象验收。
2. 对自己的实际运行程序生成截图并用view_image实际打开查看。只保存图片、看代码或看自动测试输出不算完成。UI/图表任务不以AI生成效果图代替实际截图。
3. 以相同或可换算的逻辑尺寸对照原图，逐项检查：外壳/导航、标题文件区、Pivot、模式分段、筛选日历、KPI、图卡头部、图形切换、图例、坐标/网格、公司及周期颜色、布局对齐、留白、滚动。
4. 检查当前改动涉及的交互态：hover、pressed、focus、disabled、弹出菜单/日历、空值/无历史/错误、全屏。至少检查基准1600×1000及受影响的窄窗；完整DPI矩阵可留最终验收，但须明确未检查项。
5. 做需求自查：是否把旧模式逻辑带回、是否多出/漏掉指标、是否隐藏真实缺失/虚构数值、是否越界编辑他人文件。纯数据会话只需此项及模型证据，不伪装做了UI视觉检查。
6. 发现明显与原图/MD不符项时自己修复再提交，不能把明显问题留给主会话碰运气发现；依赖未就绪必须明确标为未验证，不称完整验收通过。
