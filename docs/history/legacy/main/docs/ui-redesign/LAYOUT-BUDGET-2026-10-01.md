# 公司图幅和筛选布局修复

范围：公司页三种分析模式筛选网格、同位置折叠按钮、摘要折叠后现有图卡与实际绘图区的高度分配。保留城市无公司/模式的语义，不重新解析存档。

已复现的问题：原六项定向检查均失败，摘要动画结束不会增高图卡；同期切换会改动主筛选项位置。CompanyGroup 的直接父对象为 group_host，原结束回调没有找到 Dashboard；图卡还受 520px 上限限制。

实现：摘要动画通过真实祖先 Dashboard 逐帧使用当前 summary surface 高度预算；取消固定图高上限，多公司图表按可见公司网格行数和实际间距扣除 chrome。后续只调整已有图卡高度，并降低缩小时的绘图区最小高度，避免重建 ChartView。初次 compact 初始化仍保留原配置入口。

筛选：公司/网络主字段固定宽四列、窄两列。详情区左侧为实际范围，右侧固定 220×36 的对比占位，仅对比字段随模式显隐；宽窗口详情与操作组同行，窄窗口详情一行、操作组固定末行。城市保留独立紧凑布局。同一 SummaryToggleButton 在固定右上角 host，展开/收起仅旋转 chevron；旧 confirm/expand 属性指向同一对象。

共享 motion、chevron、elevation、filter transition 控制器由全局 owner 维护。本轮核验明确开启测试动画策略；系统 Windows SPI 禁用动画时遵从系统策略，不能将 offscreen 过程帧声称为原生 Mica 或物理屏幕验收。

验证：88 项相关检查通过（含公司三模式/城市路由/筛选/加载），其中 7 项定向检查覆盖逐帧单调伸缩、实际 plotArea 增长、ChartView 身份保留、展开恢复、同位置按钮反转、主筛选与操作物理锚点和筛选高度稳定。

实际双公司缓存证据共 36 状态：1440×960、1920×1500、920×680 × 默认/多公司/同期 × 展开/摘要折叠/全部折叠/恢复。均无横向滚动、无图卡交叠。1920×1500 三模式筛选展开高度均为 127px，折叠为 40px；默认及同期图卡高度 531→619→663px，多公司 501→605→649px，底部余量 0–1px，恢复准确。小窗按最低可读图高纵向滚动。截图仅 Qt offscreen 缓存测试。证据脚本 qa_layout_budget.py 仅读取实际双公司 session 缓存。窄窗口超出最低可读图卡高度时允许纵向滚动，横向滚动及图卡交叠不允许。
