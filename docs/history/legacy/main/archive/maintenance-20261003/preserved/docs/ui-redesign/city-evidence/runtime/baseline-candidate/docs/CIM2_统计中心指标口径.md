对 SHA-256 为 `540AA6635FC2C06EE2CC5162C57C0E609435FAC3F63A9DE08A432CAB92C302FF` 的 Modifier 程序集快照做元数据与 IL 操作码对比：`DataSerializer`、`HistoryData`、`CompanyData`、`DataManager`、`PlayerData` 的字段名及顺序、方法名和操作码序列均与审计基准一致；`CitizenData` 字段名及顺序一致，新增的方法与变化的操作码序列集中在日程生成、`TickIdle` 和 `TickInit`。这是结构比较，不等同于证明所有运行结果完全相同。用该原版探针解析两份 Modifier 工程保存的 `.save` 样本，均完成历史、线路及双工作簿输出；单人 `秋山市n3.save` 的 62,671 条历史记录及当前公司价值在原版探针与此前探针下完全一致。

- 多人样本模拟时间为 `2013-04-10 23:59:22`，`DataManager.m_lastTime=2013-04-10 23:00:00`，221 个序列的当前槽均标为 `23:00`。一般增量当前槽是正在形成的小时量；时点值显示原观测时间，比较提醒仍要求完整时间窗。超出模拟当前时间的记录不纳入计算。

## 可执行指标字典

实现位于 `src/statistics_model.py` 的 `METRICS`。原值和分母始终保留；只将下列经核对的换算用于图表，其他字段可从原始 CSV 查询。

| 指标 | 归属 | 数值含义与换算 | 聚合 |
| --- | --- | --- | --- |
| cashflow | 公司 | `CompanyData.SimulationTick` 中 `HistoryData.AddData` 的每小时净现金流；内部金额 `/100` | 有效小时求和；制式及 misc 可相加 |
| company-value | 公司 | net-cash、infra-value、vehicles-value、business-value；IL 先将分项内部金额 `/100` 再 `SetData`，因此历史原值已是货币单位，统计时不能再除以 100 | 分项期末；四项相加为价值，不跨小时相加 |
| monthly-ticket、coverage、popularity | 公司 | 原始分子／分母，显示 `100×分子÷分母` | 增量序列跨小时汇总分子分母后计算 |
| satisfaction-speed/cost/quality | 公司 | 原始分子／分母转成评分；负分子合法 | 汇总分子分母，允许负值 |
| reputation | 公司 | 分子／分母为时点状态；不按小时累加 | 期末比例 |
| linecount、stopcount、depotcount | 公司 | 游戏历史数值；站点不从线路站点记录推算 | 各分组期末；站点跨制式不自动当作去重总量 |
| vehicles-running | 公司 | `CompanyData.SimulationTick` 在小时边界设置的固定点小时运行均值，`/1024` | 已记录小时平均；未完成当前槽参与已记录值与小时权重，但完整度仍标记部分；不能当拥有车辆数 |
| transport-by-group、transport-by-type、trip-types | 公司 | 已记录的小时计数；trip-types 的 single-line/one-zone/... 是票制／覆盖区数类别 | 各类别求和；不解释成地理 OD |
| transfer-coefficient | 公司 | 同窗口分制式客流合计／分区出行量合计 | 汇总分子分母后相除；原始比值不裁剪；不生成好坏提醒 |
| population | 全市 | 社会群体人数 | 期末；群体相加为总人口 |
| economy | 全市 | growth、interests 原始分子／分母 | 分组分别取期末百分比；不能相加；无 GDP 字段 |
| energy-prices | 全市 | electricity、fuel 原始价格；物理/货币单位未确认 | 分组分别取期末原值；不能相加；禁用业务变化告警 |
| public-transport、private-motoring、walking | 全市 | 各群体出行方式分子／分母 | 加权方式占比；不强制三方式归一 |
| trip-number | 全市 | 群体小时出行次数 | 有效小时求和 |
| traffic-density | 全市 | Road/Track 的游戏加权交通密度；显示为分子／分母 × 100% | 城市卡片分别取所选范围内最大小时记录；切换日/周/月不改变峰值。无量纲，不表示车辆数、车流量或具体路段最大密度；两制式不能相加 |

`trip-time` 虽带百分比标志，但实际表示行程时间而非百分比，未进入关键卡片或告警。`fare-dodging`、`generic-ticket`、`unemployment` 等仍在完整原始文件中，第一版不猜测额外单位。月票只用 `monthly-ticket` 自己的分母；不借全市出行量。零分母显示不可计算，缺失观察不补零，真零保持零。部分自然周期、缺小时与未完成当前小时标注“已记录部分”，不生成业务告警。

## 换乘系数判定

本次实现的 `transfer-coefficient` 是公司时段统计比值：同公司、同时间范围的 `transport-by-type` 全制式合计除以 `trip-types` 全类别合计。`transport-by-group` 仅用于核验分制式总量，不与其相加；分区类别为 single-line、one-zone、two-zones、three-zones、four-zones，不是地理城区。

查询按公司标识分别计算，分类显示开关不改变分子分母。小时、日、周、月和整个区间均先汇总计数再相除，不平均小时系数；某小时分母为零时保留其分子，供分母非零的更长时段汇总。Bucket 保留分子、分母、两类原始记录、观测时点与完整度。缺失输入不补零；分子分母观测小时不匹配时不计算比值。两侧同时缺失的小时不产生观测值，已有配对观测可汇总，但完整度为不足。未完成槽的已有值保留，完整度沿用原查询规则。页面不可计算数值用“—”，系数保留两位小数，实际查询和导出不截断小数或异常比值。系数不生成好坏评价提醒。

该指标不等同于全市去重完整公共交通行程的平均乘车段数，也不据此推断每次完整行程的平均换乘次数。两字段触发阶段不同、跨公司归属和完整行程去重的限制仍成立；这些限制不阻止按已确定公司统计口径展示比值。`calculate_transfer_coefficient` 保留原独立计数定义助手供兼容，页面使用 HistoryStore 的新指标查询。

批量接口位于 `src/dashboard_model.py`。FilterState 固定单个查询状态，DashboardResult 保存各看板总量、原分类、对比与提醒供界面和导出共同使用。默认时间窗口截至模拟当日零点，向前七日；不截掉缺失日期、不填零。空公司选择只清空公司结果，城市仍查询一次；城市方式维持三个独立比率，不强制归一。提醒复用已有阈值与完整度规则，复合城市方式不重复生成源指标提醒。取消回调在查询前、序列扫描、周期聚合、系数组合和返回前检查并抛出 QueryCancelled；页面 worker 的停止和 token 拒收由页面负责。

已核查历史范围的参考系数为约 3.1513、2.6771、2.4776，不能作为默认七日结果。本树现有多人 CSV 的完整保留范围为 2013-04-01 08:00 至 2013-04-11 00:00（右端不含），独立原始计数复算为约 2.6828、2.4842；两公司的分群体和分制式合计一致。自动测试比较原始计数与四种粒度的查询汇总，未将不同历史范围的参考值写成断言。

## 已知边界

历史数组只保留最近 768 小时；早于窗口的部分是缺失，不补推。公司价值的净现金分项可能为负，满意度可负。现金流历史需 `/100`，公司价值历史已经在写入前 `/100`，能源价格只显示原值。变化提醒仅在两个等长且各小时完整的窗口计算；当前未满小时的增量量会抑制提醒。已记录当前小时会同时计入聚合值与“每记录小时”的分母，避免汇总粒度改变数值。

多人真实样本的两家公司当前快照公司价值分别为 12,052,186.31 和 11,222,126.57 货币单位；四个 `company-value` 历史分项当前槽合计分别为 12,052,183 和 11,222,125，差 3.31 和 1.57，符合分项写入取整及快照时点差。统计中心显示历史合计原值，不重复缩放。


## 独立复核后的身份与聚合修正

`load_session` 在所有关联前统一公司身份。优先保留源公司标识／玩家 ID，再按公司序号映射，旧数据仅在原始公司名称唯一时回填身份；显示名称映射不参与关联。公司和线路同时提供“公司标识”“原始公司名称”“公司名称”。重名而无身份的数据保持未关联，不能并入任一家已知公司。线路键、车型、班次、站点、车辆、公司汇总和排行均按稳定身份关联。

比例流量汇总保留已记录但分母为零的桶的分子。例如 10/0 与 20/10 在小时、日、周、月汇总均为 300%，最终分母为零仍不可计算；完全缺失桶保持缺失，单侧输入缺失不补零。存量和时点比例的跨分类合计只使用时段最后观测时刻的各分类可用值，不能把较早时刻的其他分类值搬到期末；缺失完整度和原始记录保留。

真实链路回归通过 `load_session → HistoryStore → build_dashboard` 并使用页面公司标识筛选：冻结单人 n4 样本 2013-04-01 08:00 至 2013-04-04 22:00（右端不含）约 3.1513；多人样本至 2013-04-10 23:00 约 2.6771、2.4776。三个结果在四种粒度汇总一致，分群体／分制式总量一致。冻结单人样本元数据日期晚于其历史数据，参考验收窗口按客流当前槽截止，未改写生产模拟时间或默认窗口。
