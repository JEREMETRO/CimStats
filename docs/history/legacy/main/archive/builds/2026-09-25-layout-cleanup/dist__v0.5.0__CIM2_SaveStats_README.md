# CIM2 SaveStats

当前版本：**0.5.0**。本地正式包见 `archive/versions/v0.5.0/package/CIM2_SaveStats.exe`。
版本变更见 `CHANGELOG.md`，开发、测试和发布规范见 `docs/DEVELOPMENT.md`。
当前界面仅提供统计查询与导出；不可用的班表编辑、方案组入口已移除。
旧研究记录和界面备份已整理至 `archive/history/2026-09-25/`。

Cities in Motion 2 v1.6.3 存档统计解析程序。程序使用游戏 `DataSerializer` 读取存档对象图，在隔离程序集副本中绕过 Unity 原生单例和构造函数副作用；不会修改原始存档或 Steam 安装目录中的程序集。

## 目录

- `src/`：当前解析器、Unity 探针和 XLSX 工作簿生成器。
- `data/`：原始存档、运行时依赖和解析产生的 payload。
- `exports/`：当前 CSV、诊断 JSON 和 XLSX 结果。
- `docs/`：字段字典和解码说明。
- `archive/recycle_bin/legacy_code/`：早期探测/推断脚本及中间产物。
- `archive/recycle_bin/legacy_exports/`：旧版或推断标签导出表，未作为当前结果使用。
- `archive/recycle_bin/`：已弃用的历史脚本与历史导出数据，作为可恢复备份保存，不参与当前流程。
- `docs/可统计字段清单.md` 和 `CIM2_可统计字段清单_*.csv`：当前对象导出字段、记录数和可派生统计说明。
- `docs/CIM2_居民出行需求_票价与换乘函数关系.md`：基于 v1.6.3 `Assembly-CSharp.dll` 的居民方式选择、票价计算、寻路代价和换乘机制反编译报告。
- `docs/CIM2_多人模式同步与共同模拟机制.md`：多人开局参数、玩家动作帧、锁步推进及主机/客户端模拟职责的反编译报告。

## 使用

### 单文件桌面版

发布包只需要 `dist/CIM2_SaveStats.exe` 和同目录 README。双击 EXE 即可启动，不需要安装 Cities in Motion 2、Steam、Python、Qt 或单独的后端文件；v1.6.3 游戏托管程序集及其依赖、Unity 探针和车型目录均已嵌入 EXE。冻结版只使用 EXE 内的程序集，不会回退读取目标设备上的 Steam 安装目录。窗口支持将 `.save` 文件直接拖入，或点击“打开存档”选择文件。解析完成后可以再次拖入/打开另一个存档，当前数据会在新任务开始时清空并由新存档覆盖。

程序不修改原始存档。解析临时文件写入 EXE 同目录的 `jobs/`，工作簿可在“导出工作簿”页另存到指定位置；中文文件名和中文目录路径均按 Unicode 处理。

在项目根目录执行：

```powershell
py src\extract_runtime_data.py data\望春市6.save
py src\build_cim2_workbook.py 运行时
py src\extract_runtime_data.py data\quicksave.76561198362520556-76561198845688243.save
py src\build_cim2_workbook.py quicksave.76561198362520556-76561198845688243_运行时
py src\build_line_workbook.py quicksave.76561198362520556-76561198845688243_运行时
py src\build_company_workbook.py quicksave.76561198362520556-76561198845688243_运行时
```

解析器自动定位不同存档头长度后的 raw DEFLATE 数据。多人存档会输出 `CIM2_公司信息_*` 和 `CIM2_公司车型数据_*`，并在线路、配车、时刻表、发班记录和站点表中附带公司归属字段。

### 线路显示与验证

线路名称统一规则：空名显示线路号加“路”；短名称追加末尾（如 `12路A`）；
数字开头的名称原样显示（如 `101快线`）；其他长名称用“·”连接。
原始线路号仍用于关联数据与筛选，不受显示名影响。

线路列表新增“今日平均单班人次”和“今日平均车公里人次”，沿用已有统计口径：
今日客流分别除以当日计划发班数、当日计划发班数乘地图里程，分母为零显示零。

测试：`py -3.12 -m pytest -q`。独立输出构建：
`./build_portable.ps1 -OutputDirectory dist/v0.5.0`。

`quicksave.76561198362520556-76561198845688243.save` 包含 2 个公司：

## 整理工作簿

- `CIM2_线路发班整理_*`：包含线路信息、公司概览和每条线路独立工作表。线路信息中的开线日期取线路对象的 `ObjectData.m_buildTime`，线路车库取线路关联车库，最近改线日期取 `LineData.m_lineEditTime`，单程时间取 `LineData.m_estimatedDuration`，理论最大车辆需求数（即最大配车数）取按时刻表重算的 `LineData.m_vehiclesNeededTop`。单程时间和行车总时间统一以分钟显示。各线路工作表按日期掩码展开为周一至周四、周五、周六、周日四组，把同线路的全部时刻表合并后在组内按发班时间排序；掩码 62（周一至周五）会同时出现在前两组，掩码 65 会分别出现在周六和周日。
- `CIM2_公司信息整理_*`：包含公司信息、人员表、票价表、周收支表四张表。线路客流已并入线路发班整理工作簿，不再单独生成客流 XLSX。
- 线路信息中的平均客流按累计客流除以开线日至存档当前时间的天数计算；交叉验证两条人工校准线路后，线路每周收入/支出按原始字段除以 `102400`，线路长度按原始字段除以 `1024000`。
- 公司表1的资金、公司价值及各项资产价值按 `100` 缩放；票价和人员工资也按 `100` 缩放。
- 公司表1的声誉原始值按 `1,000,000` 为满值，当前为百分数数值，例如 `873873` = `87.3873%`。
- 公司周收支表的车型收入/支出按 `100` 缩放；电力、维护、驾驶员估算分别按约 `2048`、`40960`、`97654` 缩放，以匹配游戏界面量级。
- 公司周收支表不再输出“运行班次数”列；时刻表发班数量仅在线路信息表和各线路工作表中按日期掩码展示。
- 当前替换后的 quicksave 解析结果为 2 个公司、73 条线路、167 个配车对象、438 个时刻表和 11,967 条发班记录。

### 线路长度说明

多人存档中 `LineData.m_lineLength` 是按线路保存的缓存字段。该 quicksave 中部分线路的原始字段为 0；当前线路工作簿同时保留非终端路径所引用 `RoadData.m_length` 的地图里程，以及按游戏 `CalculateSegmentLength` 得到的折算里程。路径终端连接段和 `RoadPathSegment.m_length` 不再计入地图里程。161 路的地图里程因此由错误的 24.0809 km 修正为 7.2217 km。
